# UX 원칙 기반 회원가입(사용자 흐름) 개선 — 전체 과정

기존 서비스의 회원가입 흐름을 캡처로 받아 UX 원칙으로 진단하고, 같은 절차를 유지하되 문제를 고친 프로토타입·로고·개선 노트를 만들어 GitHub에 올린다. 이후 2차 보완(디자인 정교화, 로그인·재설정·입력 보존·접근성)과 부가 화면(탈퇴 후 재가입 등)을 같은 저장소에 쌓아 간다. 사용자는 PO/기획자이므로 결과물은 기획서·발표에 바로 쓸 수 있게 만든다. 모든 응답·문서·커밋 메시지는 한국어로 쓴다.

전체 순서: 0 입력 → 1 분석 → 2 원칙 → 3 프로토타입(1차) → 4 로고 → 5 개선 노트 문서 → 6 GitHub → 7 2차 보완 → 8 부가 화면 → 9 동기화 규칙 → 10 답변.

관련 스킬: 로고는 `mascot-silhouette-logo`, 탈퇴 후 재가입 화면은 `account-rejoin-restriction`을 함께 쓴다.

## 0. 입력 확인

- 분석할 흐름의 캡처(순서대로)와 대상 서비스 이름. 없으면 요청한다.
- 가상 서비스 이름, 포인트 컬러, 마스코트/로고 참고 이미지(있으면).
- 올릴 GitHub 저장소(`owner/repo`). 새 저장소는 만들 수 없으니 빈 저장소를 만들어 이름을 알려 달라고 한다.

## 1. 캡처 분석 (채팅 답변)

구간: 진입 → 로그인 → 입력 폼 → 암호 → 오류 처리 → 약관 동의 → 인증 → 완료. 구간마다 위반 원칙(아래 목록의 이름), 화면에 보이는 근거, 사용자가 겪는 문제, 잘 지킨 부분을 적는다. 마지막에 요약 표: 구간 | 핵심 위반 원칙 | 심각도 | 개선 방향.

## 2. 원칙 목록

| 원칙 | 흔한 위반 | 개선 패턴 |
| --- | --- | --- |
| 제이콥의 법칙 | 로그인/가입이 우측 상단에 없음, 전체 동의 없음 | 익숙한 위치·관례 |
| 발견 가능성 / 멘탈 모델 (닐슨 #2) | 계정 메뉴가 장바구니 안에 숨음 | 계정과 장바구니 분리 |
| 시각적 위계 · 피츠의 법칙 | 가입이 작은 텍스트 링크, 모바일 버튼이 멂 | 동급 버튼, 하단 고정 버튼 |
| 근접성의 법칙 | 옵션이 입력창과 멀리 떨어짐 | 관련 요소를 붙여 배치 |
| 일관성 (#4) · 사용자 통제 (#3) | 다른 도메인 이동, 새로고침하면 처음부터 | 헤더 유지, 단계별 주소·입력 보존 |
| 점진적 공개 · 목표 기울기 · 밀러의 법칙 | 긴 단일 폼, 끝이 안 보임 | 단계 분할 + 진행 막대 + 남은 시간 |
| 효율성 (#7) | 생년월일 드롭다운 3개 | 한 칸 숫자 입력 + 자동 포맷 |
| 인식 > 기억 (#6) | 플레이스홀더가 라벨 역할 | 떠 있는 라벨/상시 라벨, 수집 이유 안내 |
| 시스템 상태 가시성 (#1) | 조건 다 채워도 "90%", 중복 확인 중인지 모름 | 체크리스트 + 말로 된 강도, "확인하는 중…" |
| 오류 예방 (#5) | 손대지 않은 칸에 오류, 흔한 암호 허용 | blur·제출 후 검사, 흔한 암호·이름 포함 차단, Caps Lock 경고 |
| 오류 복구 (#9) | 모호한 오류 문구, 막힌 뒤 대안 없음 | 칸에 맞는 문구 + 고칠 방법·대안 버튼 |
| 보안 · 계정 존재 노출 방지 | 재설정에서 가입 여부 노출 | "가입한 계정이 있다면 링크를 보냈어요" |
| 지연 가입 · 소유 효과 | 가치를 보이기 전에 가입 요구 | 혜택 먼저 |
| 감정적 디자인 · 피크엔드 법칙 | 제한·실패 순간을 거절 문구로 시작 | 환영 인사로 시작 |
| 접근성 | 단계 이동이 스크린리더에 안 읽힘 | 제목 포커스, aria-live 오류, 본문 바로가기 |

## 3. 프로토타입 1차 (HTML 아티팩트 + 파일)

`artifact-design` 스킬을 먼저 불러온다. 단일 HTML, 화면은 `<section data-screen>`으로 나누고 JS로 전환한다.

1. 메인: 우측 상단 "로그인 / 회원가입" 텍스트 버튼, 계정 메뉴와 장바구니 분리, 히어로에 가입 혜택.
2. 로그인: 중립적 제목, "새 계정 만들기" 동급 버튼, 옵션은 입력창 바로 아래, 미가입 이메일이면 "이 이메일로 가입하기"로 이어 줌.
3. 가입 1~4단계(기본 정보 → 이메일·암호 → 약관 → 이메일 인증): 헤더 유지, 진행 막대 + "n / 4 · 남은 시간", 이전/다음.
   - 기본 정보: 생년월일 한 칸 자동 포맷 + 실제 날짜·만 14세 검증.
   - 암호: 체크리스트는 필드 아래 고정, 조건 3개 이내, 강도는 말로, 보기 토글, 확인 칸은 입력 후에만 "일치하지 않아요/일치해요".
   - 약관: 전체 동의(indeterminate), 필수 위/선택 아래 + [필수]/[선택] 태그, "보기" 펼침, 필수 진행 수, 누락 항목만 표시.
   - 인증: 6칸 코드(자동 이동, 붙여넣기), 재전송 타이머, "이메일 수정".
4. 완료: "보던 화면으로 돌아가기", 헤더 "○○님", 동의 내역 요약.

검증: 오류는 blur/제출 후에만, 아이콘 + 고칠 방법. 버튼을 비활성화하지 말고 누르면 오류 칸으로 포커스.

UX 노트 패널: 오른쪽 서랍(넓은 화면 기본 열림, 모바일은 하단 버튼). 화면별 "원칙 태그 · 개선 제목 · 기존 · 개선" 카드 + "화면 바로가기"(뒤 단계로 가면 앞 단계는 예시 데이터로 채움). 노트 키는 화면 이름, 가입 단계는 `s1`~`s4`, 라벨은 "01 스토어 메인"처럼 번호를 붙인다.

체험용 이메일을 데모 안내(`.demo`)로 화면에 적는다. 예: `hj@hj.com` 이미 가입, `error@hj.com` 중복 확인 실패.

디자인: 포인트 컬러 토큰(라이트/다크), 오류색은 브랜드색과 구분, `word-break: keep-all`. 마스코트는 흰 배경을 가장자리 flood fill로 투명 처리 후 data URI, 메인·완료 화면 정도에만.

아티팩트로 게시하고, `<!doctype html>`로 감싼 `index.html`도 만든다. 게시 전 headless Chrome(`/usr/bin/google-chrome` + playwright)으로 한 번 스크린샷을 보고 고친다. 흐름은 playwright로 클릭·입력해 `pageerror`가 없는지 확인한다.

## 4. 로고

`mascot-silhouette-logo` 스킬을 따른다. 요약: 캐릭터 얼굴(머리) 실루엣만 추출해 눈코입 없는 단색 심볼, 워드마크는 브랜드명 + 작은 영문 업종 태그(예: ELECTRONICS). 사용자가 "토끼 느낌/업종 느낌"을 원하면 먼저 그 방향 시안을 보여 주되, 원본 캐릭터 기반 실루엣 요청이 오면 그대로 따른다.

## 5. UX 개선 노트 문서

Claude Docs로 "<서비스명> 회원가입 UX 개선 노트"를 만든다(문서 커넥터 지침 준수, 섹션은 한 번에 하나씩 채움).

- 개요: 한 문장 결론(개선 건수, 핵심 변화 3가지) + 흐름 번호 목록 + 구간별 요약 표
- 화면별 섹션: 한 줄 요지 + 표(개선 사항 | 기존 | 개선 | 적용 원칙)
- 적용 원칙 색인: 원칙 | 한 줄 의미 | 적용 화면
- 참고: 프로토타입·GitHub 링크

개선 건수는 실제 노트 카드 수를 세어 적는다. 섹션 번호는 프로토타입 UX 노트 라벨 번호와 맞춘다.

## 6. GitHub 업로드

1. `add_repo`(push) → `git clone --depth 1`. 빈 저장소면 첫 커밋으로 `main` 생성.
2. 파일: `index.html`, `assets/`(logo-mark.svg, logo-lockup.svg, mascot.png), `README.md`(소개, 보기·GitHub Pages 설정, 흐름, 구간별 개선 표, 체험 팁, 파일 목록), `UX-improvement-notes.md`(Docs를 markdown으로 export).
3. 커밋: 사용자 계정 이름, 한국어 제목 + 본문, 세션의 Co-Authored-By 줄 → `main`에 push.

## 7. 2차 보완 (요청 시 또는 "더 다듬어줘")

같은 저장소에 별도 커밋으로 쌓는다. README와 노트 문서에 "2차 보완 요약" 표(구간 | 추가한 것 | 적용 원칙)를 둔다.

- 디자인: 참고 서비스(예: 애플 스토어) 스타일 — 투명 블러 헤더, 알약 버튼, 카드 없는 중앙 정렬 폼, 떠 있는 라벨, 회색 푸터. 포인트 컬러·로고는 유지.
- 로그인: 이메일 → 암호 2단계, 패스키, 5회 실패 시 재설정 안내. 체험 계정은 메모리 객체로(암호는 저장하지 않음).
- 암호 재설정 화면: 가입 여부를 숨기는 문구, 링크 다시 보내기, 로그인으로 돌아가기.
- 가입: 성/이름 분리, 이메일 중복 확인 상태(확인 중/사용 가능/이미 가입/확인 실패는 막지 않고 마지막에 재확인), 흔한 암호·이름·이메일 포함 차단, Caps Lock 경고.
- 인증: 정답 코드 고정(예: 123456), 자동 확인, 5회 제한, 재전송 30초 간격·3회.
- 진행 유지: 단계별 해시 주소(`#/signup/2`), 뒤로 가기(popstate), sessionStorage 입력 보존(암호 제외, 새로고침 시 2단계로).
- 접근성: 단계 이동 시 제목 포커스, aria-live 오류 안내, 본문 바로가기.
- 모바일: 이전/다음 하단 고정, 입력칸이 키보드에 가리지 않게 scrollIntoView.
- 완료: 패스키·2단계 인증·배송지 등록 안내(건너뛰기 가능).
- 사용자가 단계를 빼라고 하면(예: 휴대폰 인증) 진행 막대·단계 수·남은 시간·요약·약관 문구·노트·README를 모두 함께 고친다.

## 8. 부가 화면

- 탈퇴 후 재가입 제한: `account-rejoin-restriction` 스킬을 따른다.
- 새 화면은 `SCREENS` 목록, 해시 라우팅 가드(직접 접근 시 상태 없으면 홈으로), NOTES(다음 번호), 화면 바로가기, README 흐름·체험 팁·개선 표, 노트 문서 섹션까지 한 번에 반영한다.

## 9. 동기화 규칙 (중요)

- 같은 저장소를 다른 세션·사람도 수정한다. 커밋 전 항상 `git fetch origin main` 후 `git log HEAD..FETCH_HEAD`로 새 커밋을 확인한다.
- 원격에 새 커밋이 있으면 절대 덮어쓰지 않는다: `git reset --hard FETCH_HEAD`로 최신을 받은 뒤, 그 코드 구조(함수 이름, 화면 목록, CSS 클래스)를 읽고 내 변경을 다시 얹는다. 큰 HTML은 base64 이미지 때문에 줄이 길어 `python3 -c`로 줄을 잘라 읽는다.
- 문자열 치환 패치는 고유한 앵커만 쓰고 `count==1`을 assert한다.
- 아티팩트도 저장소 최신본에서 문서 래퍼(`<!doctype>`, `<head>`, `<body>`)를 벗겨 다시 게시해 둘을 맞춘다.
- "다시 올려줘"는 `git ls-remote origin main`과 로컬 HEAD를 비교해 이미 반영됐는지 먼저 확인한다.
- 노트 문서(Docs)를 고치면 `UX-improvement-notes.md`에도 같은 내용을 반영한다(직접 섹션 삽입 또는 export).
- 스킬 파일은 `skills` 브랜치의 `skills/<이름>/SKILL.md`에 둔다.

## 10. 답변

짧게: 무엇이 바뀌었는지, 어디에 반영했는지(웹페이지·GitHub·문서), 체험 방법, 다음에 할 수 있는 한 가지. 원격에 다른 사람의 변경이 있었다면 덮어쓰지 않고 그 위에 얹었다고 알린다. 사용한 UX 원칙을 물으면 6개 내외 핵심 원칙을 번호 목록으로, 각 한 줄 적용 예와 함께 답한다.
